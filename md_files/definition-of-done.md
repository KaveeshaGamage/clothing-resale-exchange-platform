# Definition of Done

A backlog item is considered done when all applicable criteria below are satisfied and the team has reviewed the result.

## User stories and features

- The implementation meets the agreed user story and acceptance criteria.
- The change follows the existing project structure and conventions.
- Relevant frontend, backend, and API behavior is connected where required by the story.
- Applicable input validation, access control, and error handling are included.
- The change does not introduce unrelated behavior or regressions.

## Verification

- Relevant automated tests have been added or updated and pass.
- The applicable lint, build, or type-check command passes.
- The main affected user flow has been manually checked when automated coverage is insufficient.
- Any known limitation or follow-up is recorded with the backlog item.

## Review and delivery

- Code has been reviewed by another team member.
- Documentation is updated when the change affects setup, APIs, architecture, or user workflows.
- Changes are integrated into the agreed project branch without unresolved conflicts.
- The completed item is linked to its GitHub issue and moved to the appropriate completed status.
